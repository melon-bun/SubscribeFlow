## 用户确认与验证边界

用户授权按已有三期文档及 collect_pins_web.py／collect_pins.py 原型完成 M12；遇到需要扫码的步骤先跳过，以假数据或其他方式验证，无需等待用户。原型作为业务和页面提取参考，其中独立服务、Playwright、Cookie 文件、导出目录和交互命令不引入应用。

本次使用临时数据库、固定平台响应及隔离知乎页面，连接正式 Renderer → Preload → Main → Python Adapter／Core → SQLite。**隔离验证证明开发闭环，不证明当前真实知乎站点的接口／DOM 与账号读取可用。** 公开页面读取遇到访问验证后停止；没有尝试扫码、导入原型 Cookie 或读取 Chrome 登录信息。

正式应用只访问对应平台真实会话，不会自动生成假内容；夹具只在非打包应用的明确验收模式启用。后续真实账号少量采集仍需单独验收，但按本次用户授权不阻塞 M12 开发交付。

## 实现范围

- 渠道管理增加知乎连接，昵称搜索、同名候选区分、人工确认；支持官方作者主页和作者 ID 解析。现有采集条数与同步设置直接复用。
- 独立 `persist:zhihu` Electron Session；可见官方登录页和隐藏读取共用会话。远端页面无 Node、无 Preload、启用 sandbox／contextIsolation，禁止下载和外站导航。登录窗口打开期间暂停后台页面读取。
- 新 `ZhihuAdapter` 只返回公共 Source／ContentItem／FetchPage／ContentReference／ContentPatch；Core 和数据库无知乎分支。公开 RPC、契约 1.1、schema v8 不变。
- 作者发布想法进入已有初次获取、刷新、回溯窗口、定时采集、进度指标、任务取消／等待／重试、内容整理管线。
- 官方想法链接接入已有“添加内容”：本地规范化身份、查重、正文读取、预览、优先级／标签、确认保存。没有订阅的作者也可单条保存，不创建虚拟订阅／同步 Job。
- 知乎平台样式、筛选、来源、收录方式、收件箱、日历和看板沿用公共界面。详情使用“想法正文”，保留段落；图片想法允许无文字，不伪造正文。

## 身份与内容

| 内容 | 规则 |
|---|---|
| 作者 | 平台返回的 32 位稳定 ID 为 external_id；url_token 仅作官方主页定位，不以昵称或 token 作去重键 |
| 想法 | `zhihu:pin:<想法 ID>`；链接、正文、时间和昵称均不是替代身份 |
| 链接范围 | HTTP(S) 的 zhihu.com／www.zhihu.com `/pin/<数字 ID>`，归一到官方 HTTPS；分享查询和 fragment 不参与身份 |
| 不支持 | 回答、文章、任意短链、分享文案、转发／点赞／赞同动态订阅 |
| 作者归属 | 单条返回真实作者；订阅详情必须与所订阅的稳定作者 ID 相等，否则保留为失败项 |
| 标题 | 从正文生成最多 80 字的展示标题，正文完整保存在 summary；图片为主且无文字时显示图片想法 |
| 正文 | 读取想法详情的结构化实体／正文 DOM，转换为纯文本并保留换行；不拿活动卡片的摘录当完整正文 |
| 媒体 | 保留第一张有效官方 zhimg HTTPS 图片为 thumbnail；不下载视频或整组图片 |

作者搜索与确认采用原型的官方 people 搜索流程。采集发现与单条正文均使用官方 `/api/v4/members/<url_token>/pins` 与 `/api/v4/pins/<id>`，作者稳定 ID 直接来自 pins 响应的 `author`；昵称搜索使用 `api.zhihu.com/search_v3`。`www.zhihu.com/api/v4/members/<token>` 与 `search_v3` 已返回 403 code 10003，不再使用。想法身份为官方数字 ID，列表返回的 `/pins/<id>` 一律归一为 `/pin/<id>`。

## 采集窗口、持久化和错误

窗口按主页顺序检查前 N 个不同想法 ID，N=1–50；默认刷新 8、回溯 30。置顶正常占名额，重复卡片不重复计数；已完整收录的也占名额，跳过详情后不向后补足。非发布想法动态不占想法名额；有效窗口内的身份缺失报结构变化，不能静默当作非目标内容。

每次私有请求读取一个主页批次或一个详情；Core 提交结果后再读下一条。最多 13 次主页读取，连续 3 次无新身份达到扫描上限，状态为 possible_gaps；显式页末仍只是主页窗口，不宣告完整历史。失败详情产生 ItemError，不替补窗口外条目。原位置恢复必须匹配作者、任务、模式、条数及进度版本；被其他页面导航打断时明确重试。

私有页面读取有超时和取消，单请求最长 45 秒、作者搜索 60 秒；扫描状态最多存续 10 分钟。Core 继续使用共用资源协调器和默认间隔，不为自主添加创建独立锁。取消／超时／旧连接配置的迟到结果不能保存。

认证失效、访问验证、限流、页面变化、不可访问和超时分别保留结构化状态。自动任务使用现有 Scheduler 阻塞／恢复机制，不自动反复弹登录窗口。链接身份解析纯本地、无需认证，因此登录失效时也能识别并打开已保存的重复记录；读取新内容仍要求真实会话。

## 发布时间与重复

- 原始发布时间来自想法 created／created_time，或明确“发布于 YYYY-MM-DD”的出版标签；仅日期保留日期，时分保留分钟精度。
- 编辑时间、活动时间、相对时间和当前时刻不代替原始发布时间。只有未知则保留 unknown。
- 自动内容以原始发布进入日历；未知自动内容保留在列表、不伪造日期。手动新内容按成功保存时间归档，同时保留原始发布时间。
- 两种收录顺序及重复链接均按同一稳定 ID 保留首笔完整记录，包括正文、时间、来源关系、标签、优先级和处理状态。独立补充详情按现有规则更新内容事实，不改变首次收录方式／时间。
