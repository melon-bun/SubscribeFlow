## 1. 本期产品决定

新增 `channel=wxrank`、`backend=paid-http`、展示名「公众号」的正式订阅渠道，通过第三方服务取公众号推文列表。支持添加来源、手动刷新、有上限的多页采集与历史回溯，并可按用户主动配置进行自动检查。

- `wechat`（M14）的单篇文章链接接入保持原样；本渠道不做正文、单条文章接入、搜索或导出。
- 官方文档目录另列搜索和文章内容服务；本期不接入属于范围选择，不能写成服务端没有这些能力。[供应商官方站点所链接的API文档](https://www.showdoc.com.cn/2343746579263506)。
- **积分只展示，不做本地余额／月度预算拦截。** 不新增金额上限、扣费配额或每页审批；余额不足由服务端返回错误。每次任务仍沿用必要的采集条数／页数上限，防止无界翻页，这与余额拦截不同。
- 真实密钥只从用户指定的本机凭据文件或应用受保护凭据读取；不写入方案、提示词、源码、证据、日志或URL。原稿中的明文测试密钥已移除。
- 原始实测来自 MiniMax 的2026-10-25记录；在没有脱敏原始证据和必要复验前，不能把有限样本写成接口永久保证。
- 具体实现交 MiniMax，Codex 负责分发与独立验收。不自动打包、推送或发布。

## 2. 先修正的架构判断

| 原稿判断 | 现有实现与本稿处理 |
|---|---|
| `paid-http` 自然获得 `http:wxrank` | `bootstrap.RESOURCE_KEYS` 未登记该 backend，会退回 `browser:opencli-default`。必须显式登记并测试，不与其他渠道误共用资源。 |
| 默认刷新1页、回溯3页就能决定每次费用 | `SyncService.page_budget_for` 优先按非零 `collect_items/page_size` 推导页数；填30条会变3页。UI成本与执行必须使用同一有效页数，不能固定宣称一次刷新只花5积分。 |
| 既有游标机制可直接续历史 | `_run` 每次都从 `cursor=None` 开始。必须补本渠道的有效回溯检查点，否则重复回溯只会重买头几页。 |
| 现成凭据管道加一个引用即可 | `SettingsBridge._references/_sync/prune` 当前只覆盖 `ai.providers`。须同时纳入渠道引用，否则渠道密钥会漏推、被撤销或被清理。 |
| 解析后确认添加天然不再收费 | 现有界面把 `chosen.url` 再交给 `SubscriptionService.add` 解析。必须接受自身生成的来源定位URL并命中已落盘缓存，不能仅接受裸biz。 |
| 所有biz去掉`=`再补`==` | Base64填充数取决于长度，可能是0／1／2个。应做合法性校验和标准归一化，并以不同长度样本验证；不能从一个账户推导固定补两个。 |
| 无响应就能记作未扣费 | 可能已处理而响应丢失，须保留未知结果；只显示已确认用量，不声称能精确重建服务端全账。 |

独立 `wxrank` 渠道是本期选择，方便区分付费能力和无正文内容；不是 Gateway 不允许同平台多 backend。默认连接ID冲突是 bootstrap 的生成规则限制。跨 `wechat`／`wxrank` 同文各存一条沿用原方案的明确取舍，不在本期重做跨渠道合并。

## 3. 接口与费用契约（M45.1 先冻结）

### 3.1 已知请求

固定HTTPS根地址 `https://data.wxrank.com`，只调用本期两个白名单路径，JSON请求体承载运行时密钥：

| 操作 | 路径 | 参数 | 原实测观察 |
|---|---|---|---|
| 解析公众号 | `POST /weixin/getinfo` | `key,biz` | 成功返回名称、`user_name=gh_…`、头像和简介 |
| 获取一页列表 | `POST /weixin/getps` | `key,wxid,cursor?` | 返回扁平 `list`、`wxid` 和下一页游标 |

- 原记录显示成功 `code=0` 每次5积分；`code=1000` 不能稳定区分密钥无效与积分不足；`code=1005` 曾为超时；余额可从 `msg` 的「剩余N积分」观察。具体错误映射、费率、QPS5和游标24小时有效期都需归档来源／样本后作为本次适配版本的约定。
- 同时检查HTTP状态、JSON结构与业务code；不能把「样本HTTP200」写成HTTP永远200。code须严格校验，不接受布尔值或把坏响应当成功。
- 原两页样本每页约9～10篇、只见 `idx=1`；这不足以证明永不返回副条。能力保守说明可能缺副条，`full_history=False`；若实际收到合法 `idx>1`，必须正常保存。
- 空列表是否代表当前服务数据末页应有脱敏样本；即使证明服务数据已扫完，也不声称已覆盖公众号全部历史／副条。
- 原始响应只留脱敏字段和必要样本，不保存请求体中的密钥或原始凭据。

### 3.2 身份与定位

| 对象 | 契约 |
|---|---|
| 来源键 | `wxrank:account:{gh_id}`，保存规范biz与gh_id的映射；同一来源重启后稳定 |
| 可解析locator | 裸biz，以及本 Adapter 自己返回给确认添加流程的官方域名来源定位URL；后者仅提取biz、查缓存，不访问网页 |
| 来源URL | `https://mp.weixin.qq.com/s?__biz={编码后的规范biz}` 仅作内部定位，不宣称可浏览主页；界面隐藏／禁用该来源的「打开主页」，保留真实文章原文链接 |
| 内容键 | `wxrank:article:{规范biz}_{mid}_{idx}`；从经校验的文章URL提取biz/mid/idx，并核对与当前来源一致 |
| 原文链接 | 只接受微信官方文章域名和合法路径；http升https、去片段，保留请求所需query。分享签名不参与内容去重 |
| 时间 | `pub_time` 按 `Asia/Shanghai` 解释，按上游提供的精度保存，不编造日期 |
| 内容 | 标题、封面、时间、原文；正文空，`acquisition_complete=True` 表示本渠道元数据单元完整，不代表取得正文；界面明确「仅列表信息」 |

规范化只做必要的一次URL／HTML实体处理，不能损坏query中的`+`、`&timestamp`等内容。缓存键、来源locator与内容身份使用同一规范biz。非本期可验证的输入应在发付费请求前拒绝。

## 4. 凭据、账本与缓存

### 4.1 复用凭据生命周期

`input[type=password] → Main CredentialService(safeStorage) → credentials.json → credentialRef → 私有 credential.provide → Core内存`。

- 普通设置新增 `channels.wxrank`，仅保存凭据引用及非敏感版本元数据，**不增加预算字段**。
- Main保存、引用收集、推送、撤销、prune与Core重启重推全部覆盖渠道凭据；保存其他AI设置不能清掉公众号密钥，换公众号密钥也不能清掉AI密钥。
- Core不落盘明文、不回显密钥；借用现有 CredentialBroker，不另造密钥文件或本地HTTP侧车。
- 换密钥推进调用版本，账本按不含秘密的连接／凭据版本区分，旧余额快照不得冒充新密钥余额。

### 4.2 本地用量是已确认值，不是预算

新增迁移 `015_paid_channels.sql`（开工时核对是否仍为下一号）：

1. 付费调用记录：本地attempt_id、连接／凭据版本、操作、发生时间、状态、已确认扣分、最近服务端余额及观察时间。不得包含密钥、完整请求体或敏感响应。
2. biz→gh_id及来源元数据缓存；成功解析后落盘，重启可复用。并发解析同一规范biz合并为一个在途请求，避免重复付费。
3. 回溯检查点见§5；可使用独立表或既有progress的本渠道版本化载荷，不以临时内存当持久续采。

计费状态：

- 发请求前先建立尝试记录；明确收到合法 `code=0` 就记已确认5分，包括空／坏业务data；采集结果失败不撤销已发生费用。
- 明确业务失败按已验证规则记未确认扣费或零扣费；网络超时、取消、连接断开、崩溃遗留尝试不能直接宣称没扣，显示为**结果未知／可能已扣费**。
- 自然月汇总「本月已确认用量」与「结果未知次数」；服务端余额显示为「最近一次余额＋观察时间」，解析失败或首次使用显示未知，不显示伪造0。
- 账本落盘／缓存失败应如实返回本地失败，保留可识别的未决记录；不因UI刷新重发付费请求。
- 服务端余额是该密钥的权威快照，不能据本应用账本推算其他客户端的用量。本地不依据这些数字阻断采集。

## 5. 付费任务执行：翻页、回溯与重试

### 5.1 有界分页，费用按同一执行参数展示

- 一个任务可在采集上限内自动翻页；**不在每页暂停要求确认**，也不额外扫超出上限的页。这取代原稿自相矛盾的「不自动翻页」。
- 既有非零采集条数优先于默认页数：例如30条、每页10条，对应最多3次getps、15积分；首次解析的getinfo另计5积分，命中缓存则0。
- 采集条数限制本次扫描窗口，不因重复内容已存在就继续扫更多页补新条数。页数上限由同一预算推导函数决定；9条短页不触发超上限补页。
- 默认配置使用渠道默认值时，刷新最多1页、回溯最多3页。UI应展示实际推导出的本次最多调用数／费用，不硬编码「一次刷新5积分」。
- 空页也可能收费。用户主动开启自动检查时，明确每次检查也会调用付费接口；默认仍为手动，不悄悄启用周期消费。

### 5.2 真正推进历史回溯

- 刷新从头部开始；回溯从最后一次**已提交成功页**的本渠道检查点继续，持久保存下一cursor、取得时间／失效时间、来源与解析／连接版本。
- 页面数据与可继续游标的推进在同一提交边界内完成。失败、重启或重复回执不得跳过未提交数据，也不把重复页认作新的历史进度。
- 必须调整当前SyncService的检查点装配：它现在每轮初始化 `cursor=None`。新规则仅对声明了本能力的渠道生效，既有渠道恢复语义不变。
- 到期或版本不兼容不得静默复用；清楚标记需从头重建的回溯，并在重新扫描前展示相应调用成本。不能把从头重扫描述成续采成功。
- 只在有终止证据时标记服务当前数据集扫完；覆盖说明仍保留副条／上游历史范围的限制。

### 5.3 重试与资源

- 付费请求不做HTTP层自动重试，也不允许现有Scheduler根据通用 `TIMEOUT/TRANSIENT/retryable` 静默重放扣费结果不明的请求。
- 默认让失败回到可手动重试状态；人工重试明确可能再次收费。即使1005样本未扣费，也不默认开启整任务自动重放；以后若改变政策须单独说明哪类响应可安全重试、从哪页继续。
- 正常用户配置的下一周期检查与错误自动重试区分记录；遇密钥无效／余额不足或扣费未知，不自动从第一页反复重买。
- 在 `bootstrap.RESOURCE_KEYS` 显式登记 `paid-http → http:wxrank`；资源互斥、QPS节流、同biz解析合并覆盖解析、测试和采集全部付费入口。
- 串行不等于限流：同一时刻至多一个请求，仍按已核对的QPS做起始时间节流。不要持有同一不可重入锁再嵌套获取造成死锁。
- 网络调用离开Core事件循环（与现有GitHub传输一样），超时服从Context截止时间；取消／退出不得卡住主界面或等待无界网络。迟到响应不能写入已关闭数据库，未知费用仍可追溯。

## 6. 界面与公共调用

### 6.1 渠道卡片

显示「公众号 · 付费API」，提供密钥配置、服务端最近余额、本月已确认用量、未知次数、单次费用与限制说明。不显示不存在的本地预算上限。

- 「检查配置」不发网络请求，只检查本地是否有可用凭据；文案为「已配置，未联网验证」，不假称密钥有效。
- 真正联网验证是独立「测试接口 · 预计5积分」。必须有用户提供／选定的biz，明确绕过解析缓存，否则不能证明新密钥有效；结果同样记账。不得为自动探测反复消费。
- 添加来源：显示冷解析费用；确认添加再次解析自身locator应命中缓存，不再收费。
- 刷新／回溯：展示按配置推导的任务成本上限；「查看积分」仅读本地快照，不偷偷调用上游。
- 无可浏览主页时隐藏／禁用主页按钮；原文按钮继续使用已验证的真实文章地址。
- 文案区分「本次采到0条新内容」和「没有付费请求」，重复／空页仍可能产生费用。

### 6.2 受限桥接

可按实际职责确定命名，至少覆盖：保存渠道凭据、读取本地用量、显式付费测试、清理来源解析缓存。所有新增方法须同步 Renderer AppClient、Preload、Main受控入口与Core RPC，并用正式Renderer验证；不要复发BUG-124／125式只补一层。

原始settings写入和凭据私有桥仍不向Renderer开放。设置接入复用既有事务与密钥恢复，不接入AI Provider配置来冒充采集渠道。

### 7.1 分批执行方式

- **第一批：M45.1～M45.3。** 原MiniMax session `mvs_d536c17e5d0d40b4a465779846432b27`，coding模式；先冻结契约，再完成迁移／凭据与单页业务，不碰真实收费。

- 不逐模块要求用户确认，不为非致命外观或镜像测试形式单独返修。启动失败、数据／统计／费用错误、配置不生效、采集／导航完全不可用、退出卡死作为实质门槛；计划主要能力必须完成。

- 实施启动后沿用每20分钟状态检查；同批连续两次定时未完成才要求尽快收尾，不设硬时限、不重复启动同一session。以新建的M45持久状态为入口，不复活已完成的M36～M44任务。当前仍为方案阶段，未启动开发或自动化。
