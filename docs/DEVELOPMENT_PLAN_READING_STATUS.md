# 阅读状态命名与「通用」设置开发方案

日期：2026-11-04（Asia/Tokyo）

状态：源码实现与隔离验收完成；尚未生成或安装新应用包。

代码基线：`07d76a5`，当前产品版本 `0.5.3.4`。

## 1. 目标与概念

把阅读后的两种去向明确区分开：**还会再看**表示读过、值得重访；**看完了**表示本轮阅读已经结束，可以收起。仅使用「已读」无法表达是否还会重访，与「归档」容易混淆。

| 内部状态 | 当前界面叫法 | 新默认名称 | 含义 | 可重命名 |
| --- | --- | --- | --- | --- |
| `read` | 已读 | **还会再看** | 已经看过，但还准备再次查看 | 是 |
| `archived` | 归档／已归档 | **看完了** | 阅读已结束，目前不准备继续查看 | 是 |
| `deferred` | 稍后／稍后处理 | **稍后阅读** | 留待之后阅读，还没有完成处理 | 否 |
| 三项均为 `false` | 未处理／收件箱 | 保持原有名称 | 尚未选择上述去向 | 否 |

本方案按用户的「稍后阅读」统一 `deferred` 的完整显示名称，消除现有「稍后」「稍后处理」混用。普通句子中「可稍后处理」等时间表达不属于状态名，无需机械替换。

「看完了」仍是整理状态，不代表删除内容；内容继续保留在对应分类、全部更新、笔记关联内容等入口中。「还会再看」也不新增提醒任务或自动回访计划。

## 2. 范围与不变项

本期包含：全应用状态名称与相关句子统一、设置新增「通用」、两项名称的校验与持久化、保存后的全局生效，以及旧数据兼容验收。

沿用现有互斥处理状态：`read + archived + deferred <= 1`。点击一项会清除另外两项；再次点击已选项时，沿用当前取消状态的行为，回到未处理。操作仍经过现有状态保存、即时选中反馈、失败回退与统计刷新链路。

不修改数据库内容状态字段、RPC 状态参数、筛选值、路由状态值及计数键；内部继续使用 `read`、`archived`、`deferred`、`unread`、`high_unarchived` 等稳定标识。既有「已读」内容直接显示到「还会再看」，既有归档内容直接显示到「看完了」，不批量改写历史状态。

不增加状态、不改变排序或优先级算法、不把打开原文或打开详情自动视为已读，不改变提醒集合与触发规则。版本升级、打包与发布另行安排。

## 3. 设置 → 通用

### 3.1 入口与布局

在设置左侧导航首位新增「通用」，放在「AI API 配置」之前。新增路由 `#/settings?section=general`；未指定分区时默认进入「通用」，已带分区参数的入口继续直达原分区。

本页只放一个「阅读状态名称」区块，沿用现有设置表单与底部保存／取消布局，不加入其它通用选项。

```text
设置
  通用                    阅读状态名称
  AI API 配置
  提醒设置                还会再看    [ 还会再看             ]
  优先级设置              看完了      [ 看完了               ]
  AI 总结                 稍后阅读    稍后阅读（固定名称）
  外观
                          恢复默认名称

                          取消                    保存
```

字段标题「还会再看」「看完了」使用固定的默认名称，输入框显示当前保存名称，避免改名后失去对应关系。「稍后阅读」只显示文本，不提供输入框、编辑按钮或保存字段。

页面用一句简短说明「只修改显示名称，不改变内容的阅读状态」。两项状态的概念说明可放在字段帮助中，不新增冗余副标题。

### 3.2 编辑与保存

- 输入只改变当前页草稿，保存成功后才影响应用；失败保留输入并显示字段错误。
- 「保存」只提交「通用」，不覆盖其它分区草稿。无改动时按钮不可用；保存期间锁定相关表单，防止重复提交。
- 「取消」恢复本页最近一次已保存值；切换分区保留草稿，离开设置时沿用现有保存／放弃／继续编辑流程。
- 「恢复默认名称」将本页两项草稿恢复为「还会再看」「看完了」，仍需保存才生效。
- 保存成功后立即更新主界面、主进程托盘和后续通知，无需重启；重启后保留名称。已发出的系统通知不追溯修改。

### 3.3 名称校验

以下是本方案建议采用的产品规则，前端与 Core 保持一致，Core 为最终校验方：

| 规则 | 处理 |
| --- | --- |
| 类型 | 只能是字符串 |
| 首尾空白 | 保存前去除 |
| 长度 | 去除首尾空白后 1–12 个 Unicode 码点，与现有优先级名称上限一致；前端不直接使用 UTF-16 的 `length` 计数 |
| 空值、换行与控制字符 | 拒绝，错误定位到对应输入框 |
| 两项同名 | 拒绝；用去除首尾空白、英文字母不区分大小写后的名称比较 |
| 占用固定状态名 | 拒绝「稍后阅读」「稍后处理」「稍后」「未处理」「未读」「收件箱」，避免与固定状态及其现有入口混淆 |
| 非白名单字段 | 拒绝 `deferred`、`unread` 或其它未知状态键，不能绕过界面改名 |

校验比较使用归一化值，保存时保留用户输入的大小写与内部空格。两项一起校验、一起保存，任一非法则整次提交失败。渲染时按纯文本输出，不能把自定义名称作为 HTML、选择器、类名或路由值。

## 4. 全应用名称与句子规范

### 4.1 统一名称来源

建立按稳定状态 ID 取当前名称的公共入口，例如 `SF.catalog.readingState(id)` 和 `setReadingStateNames(names)`。Renderer 各页面每次渲染从这里取名称；不能在初始化侧栏时把旧名称永久复制进静态数组。

Core 提供权威默认值、合法名称与读取回退；Renderer 与 Main 保留同一份默认值作为启动兜底。Main 建立轻量阅读状态名称模块，沿用现有 `priority-labels.cjs` 的设置同步方式。增加契约断言，防止三端默认名称或固定状态名漂移。

用户自定义的名称可能是任意名词或短句，组合文案统一用引用名称的方式，不直接拼接「已」「未」「尚未」等前缀。例如把「未归档」改成「不在『看完了』中」，而不是「未看完了」。实际界面使用中文引号「」。

| 场景 | 新默认文案／生成规则 |
| --- | --- |
| 分类、标题、筛选、状态徽标 | 当前状态名称，如「还会再看」「看完了」「稍后阅读」 |
| 单条与批量设置动作 | 按钮直接使用当前名称；需要动词的菜单使用 `移至「{名称}」` |
| 取消已选状态 | `移回收件箱`，不再显示「标记为未读」 |
| 提示、读屏标签、成功反馈 | `移至「{名称}」`／`已移至「{名称}」`；取消时按返回收件箱表述 |
| 收件箱说明 | `选择「{read名称}」「稍后阅读」或「{archived名称}」后，会移出收件箱。` |
| 全部更新说明 | `查看所有已保存的内容。` |
| 重访分类说明 | `已经看过，之后还准备再次查看的内容。` |
| 完成分类说明 | `阅读已结束，暂时收起的内容。` |
| 待处理提醒说明 | `收件箱与「稍后阅读」的并集，不包含「{read名称}」和「{archived名称}」。` |
| 高优先级未归档列表标题／托盘项 | `不在「{archived名称}」中的{高优先级名称}`，计数按原口径追加 |
| 对应列表说明 | `最终优先级为「{高优先级名称}」且不在「{archived名称}」中，包含「{read名称}」内容。` |
| 通知正文 | `你有 23 条内容未处理；另有 5 条「{高优先级名称}」内容不在「{archived名称}」中。两个数字可能重叠。` |

上述句子也必须适用于自定义名，例如 `read=值得重温`、`archived=已结束`。不得为自定义名保留默认名称的旧前缀、缩写或硬编码提示。

## 5. 配置契约与兼容

### 5.1 数据结构

复用 SQLite `app_settings.payload` 的 JSON 配置，新增：

```json
{
  "general": {
    "readingStateNames": {
      "read": "还会再看",
      "archived": "看完了"
    }
  }
}
```

只存储两项可编辑名称。`deferred` 的「稍后阅读」由固定目录提供，不进入可编辑配置。不新增表或修改 `content_states`，本功能不需要提升数据库 schema 版本。

沿用现有 `getSettings`／`saveSettings`、`settings.get`／`settings.update`，保存请求示例：

```json
{
  "section": "general",
  "patch": {
    "readingStateNames": {
      "read": "值得重温",
      "archived": "已结束"
    }
  }
}
```

支持只提交其中一个合法名称，与当前另一项合并后再校验重复；空对象、未知字段及凭据参数均拒绝。字段错误沿用 `INVALID_INPUT` 与 `scope=field`，`scope_key` 使用 `readingStateNames.read` 或 `readingStateNames.archived`，按现有设置错误映射落到本页输入框。

`snapshot()` 与 Main 的脱敏快照都返回完整、有效的 `general`。保存只推进设置总版本，不推进打标、智能优先级或总结策略的 revision，不触发重跑、采集或付费调用。

### 5.2 旧配置与异常读取

- 旧配置没有 `general`：读取时返回两个新默认名，历史内容状态与其它设置均保留。
- 容器类型错误或单项缺失／非法：读取时以默认值补齐；不因名称损坏导致整个设置页不可用，不在读取时写回数据库。
- 回退后两项发生重名、或存档中的两项互相同名：整组回退默认名称，保证返回的两个名称有效且可区分。
- 存档里出现 `deferred` 等未知项：不对外生效；后续保存 general 时只写合法的两项名称。
- 启动设置读取失败：界面和主进程先使用默认名称，成功重读后同步真实配置；不能把自定义名清空后保存覆盖。

### 5.3 保存与同步边界

SQLite 提交成功后，以 Core 返回快照统一更新 Renderer 名称目录与 Main 名称缓存，并刷新侧栏、当前视图、托盘菜单。避免页面已改名而通知仍使用旧名。保留当前筛选 ID、已选内容、详情滚动与其它分区草稿；只改文字不应触发内容状态写入。

当前 Main 已有优先级名称同步链路，实施时扩展同一设置读取／保存接点。Core 重启恢复后的设置读取也要覆盖 general。若设置已提交但后续界面同步失败，应按已保存处理并提示重读，不能误报整体未保存或回滚已落库配置。

提醒集合继续使用现有谓词：

- 待处理：未处理与 `deferred=true` 的并集，排除 `read=true` 和 `archived=true`。
- 高优先级未完成集合：最终优先级为 high 且 `archived=false`，**包含 `read=true` 的「还会再看」内容**。

因此「还会再看」仍可能进入高优先级提醒。这是现有行为的延续；本期只调整名称和说明，不修改提醒规则。
