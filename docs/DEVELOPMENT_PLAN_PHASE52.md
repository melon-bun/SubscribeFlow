## 2. M33 详情读数真实取数

### 2.1 读哪些字段

按「静流」方案 §8 的原始约定：

| 读数 | 数据来源 | 说明 |
| --- | --- | --- |
| 采集时间 | `contents.first_seen_at` | 收录时间 |
| 详情完整度 | 载荷里已有的 `acquisition_complete` | 布尔值 |
| AI 打标 | `tagging_tasks` 的 `state` 与 `applied_count` | 任务状态与打上的标签数 |

**没有数据的字段直接隐藏，不显示占位。** 这是方案原文的要求，也是 5.1 期写进方案文档的约定：
读数条不能为了「看起来完整」而显示假值或 0。

### 2.2 实施前必须先核实的三件事

这三项都涉及数据层，**不能照方案文字直接写**，必须在动手前用实际代码确认：

1. `contents.first_seen_at` 是否已经在 `content.list` / `content.get` 的 DTO 里透传？
   若没有，需要在 Core 的 `contentDTO` 与 Main 路由补字段——这会动到数据契约，
   要在本文档记录后再实施。
2. `acquisition_complete` 当前在哪些载荷里存在？它是 content 的字段、source 的字段，
   还是采集运行记录上的？5.1 期读到的是内容详情页，读取路径可能与采集时不同。
3. `tagging_tasks` 的 `state` 与 `applied_count` 在 Renderer 侧能否直接读到？
   若需要新增 RPC，要按第五期的规矩同步四处：Renderer → AppClient 白名单与映射 →
   Main 路由 → Core RPC。

### 2.3 完成门槛

- 读数条显示的是真实数据，且**没有「示例数据」标注**；
- 任一字段无数据时，该项整个不出现（不是显示 0、不是显示「—」）；
- 换一条内容、一条来源、一条没有打标的内容，读数条正确随之变化；
- 5.1 期定下的版式（等宽字体、单行排布、字段密度）不变。

## 3. M34 快捷键

### 3.1 要绑定的键（方案 §6）

| 键 | 动作 |
| --- | --- |
| `J` | 下一条 |
| `K` | 上一条 |
| `E` | 已读 |
| `L` | 稍后处理 |
| `A` | 归档 |
| `O` | 打开原文 |
| `N` | 添加内容 |

### 3.2 实施前必须先确认的事

- 这些键与现有键盘操作是否冲突：产品已有 `⌘K`（聚焦搜索框）、modal 的焦点限制与
  Escape 关闭、标签编辑区的输入。**输入框内不能触发快捷键**，modal 打开时也不能。
- 键位提示样式（方案里的 `.kbd`）要跟着一起加，但**必须在功能实现之后**加，
  顺序反了就会出现「界面暗示的功能不存在」。
- 焦点在可编辑元素里时一律不触发；读屏与键盘用户要能用。

### 3.3 完成门槛

- 七个键在收件箱（及详情打开状态）下都按预期动作；
- 输入框、编辑区、modal 内不误触发；
- 键位提示出现在按钮上，且与实际行为一致；
- 5.1 期定下的视觉不变（快捷键提示用 `--font-mono`，中性色）。
