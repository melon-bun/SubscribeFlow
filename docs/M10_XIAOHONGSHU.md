# M10 小红书作者更新订阅

更新：2026-10-24（Asia/Tokyo）

状态：0.5.2 本地优化与正式包验收完成，未推送。本轮为隔离站点验证；早期真实平台验证与 M10 初版计划按下文历史日期理解。最新结果见末节及 [0.5.2 记录](RELEASE_0.5.2.md)。

## 用户决定

1. 仅订阅作者更新，添加作者采用昵称搜索 → 候选账号确认 → 保存稳定作者身份，操作方式与 B站一致。
2. 作者主页先读取笔记 ID，过滤本地已完整收录笔记，减少重复详情访问。未完成记录可重试，不能在第一条旧笔记处停止而漏掉后续新笔记。
3. 使用 [实现小红书用户搜索 Demo](codex://threads/01a0fd21-8e0b-7361-9f63-e09cfdb09074) 的方案 A，正常搜索／采集隐藏网页；首次使用或掉线后通过应用内登录恢复，模式与 B站一致。
4. M10 完成后暂不打包，先体验、排查 Bug 和优化；后续明确要求时再打包。

## 正式应用流程

- 渠道管理：小红书连接状态、应用内登录、检查连接、来源与采集设置沿用已有结构。
- 添加作者：选择小红书并输入昵称，显示昵称／头像／简介／区分账号的信息，用户选择后再订阅；无结果、搜索失败和需要登录分别展示。
- 首次连接／掉线：显示需要登录的状态与登录入口；用户在独立窗口登录，关闭窗口后检查连接，再重试搜索或采集。后台任务遇到登录或验证停止，不反复弹窗。
- 刷新／回溯：隐藏页面读取主页列表，检查笔记 ID；新笔记或缺失必要数据的记录再访问详情，已经完整入库的跳过。保留现有采集条数和任务入口，列表扫描范围与实际详情访问分开计量。
- 浏览／整理：内容进入现有时间线、日历与优先级视图，使用现有人工标签与处理状态；重新采集保留人工修改。

## 方案 A 的正式接入要求

采用 Electron 直接执行页面读取的路径。页面容器由主进程管理，保持正常尺寸和页面布局，日常隐藏；可见登录与隐藏采集共享小红书独立持久会话。搜索、主页、详情和登录对同一资源串行协调，不允许并发导航相互干扰。不依赖 OpenCLI／CDP，也不迁移 demo 或 Chrome 的登录数据。

本地参考 demo 位于 `/Users/xor/Documents/xiaohongshu_login_test/`：

- `src/main.cjs`：直接页面读取连接与独立会话。
- `src/core/page.mjs`：公开页面状态／DOM 提取。
- `src/core/workflow.mjs`：搜索、作者归属、分页、取消及部分结果。
- `src/core/time.mjs`：发布时间解析和精度。
- `docs/验证记录.md`：历史验证证据与当时未完成项。

Demo 中最近 48 小时、默认最多 8 条及 A／B 比较界面属于实验范围。正式订阅不限定更新必须发生在最近 48 小时，不保留实验切换界面。保守导航间隔、有限扫描和遇到登录／验证立即停止的原则沿用；最终参数在正式接入与实测中记录。

用户已经确定方案 A；demo 旧记录中的失败或不完整结果不代表正式应用已通过隐藏页面验收。需在当前集成中验证真实登录、隐藏搜索／采集和失效恢复，不将离线测试或既往选型结论冒充正式交付验收。

## ID 与完整性

作者 ID 作为来源稳定身份；笔记 ID 与渠道共同作为内容稳定身份。主页访问链接中的临时凭据不参与去重。主页仍需读取以发现更新，减少频率主要来自跳过重复详情。失败、占位或缺失必要字段的记录保留补全机会；置顶与乱序需要继续有界扫描，不能遇到一个已知 ID 就结束。

发布时间、作者归属和扫描完整性单独记录。模糊日期不伪造精确时间；本轮无新增、取消、超时或分页未完成均不能宣称全量覆盖。保留已入库结果、人工整理及明确的重试入口。

## 2026-10-07 实现记录

分支：`feature/m10-xiaohongshu`，基线 `main ad4ee9e`，实现提交 `8de30a6`，工作区干净。本轮未打包、未推送，日常数据与登录未操作。

### 解耦边界

- `channels/xiaohongshu/adapter.py` 独立实现渠道契约，只有 contracts、资源协调与注入的桥接依赖，不读取数据库或界面。
- Core 通过通用 Repository 查询完整收录身份，放入 `FetchRequest.known_ids`；标准来源放入 `Context.source`。这些都是稳定身份，不含页面选择器、脚本或临时访问凭据。
- `ChannelSessions` 按渠道注册／分发后端；小红书 session、API、页面提取和时间解析分文件隔离。故障不被转换成成功空列表，也不影响其他渠道的后端。
- 采集大小、默认预算、预算单位与主页扫描开销由渠道描述声明，Core 按统一规则运行。B站沿用每页 20 条；小红书每次结果是一个主页扫描步骤或一条详情，逐条提交。
- 更换后端通过 Gateway 注册与连接 backend／version 完成，既有来源／笔记 ID、订阅和人工整理保留；界面按该连接实际 backend 的能力显示，平台筛选按渠道去重。

### 采集与会话

小红书使用 `persist:xiaohongshu`，与 B站和默认 Renderer 分区独立。方案 A 通过主进程直接读取 WebContentsView 的 DOM／公开状态；没有 OpenCLI、CDP 或浏览器 Cookie 导入。隐藏窗口维持正常大小，关闭后台节流；用户关闭登录窗口时仅隐藏，保留页面和持久会话。页面禁用 Node、使用沙箱和上下文隔离，无应用 Preload；限制顶层导航、弹窗、权限和下载。

昵称搜索提供昵称、头像（若可取得）、公开简介与稳定作者 ID，用户选择并勾选确认后添加。搜索／主页返回的临时访问链接只保留在后端缓存，不进入通用存储、进度或日志。

主页按顺序取本轮窗口内 ID，完整收录记录占一个检查名额并跳过详情，不向后补位；窗口内仍不会遇到首个旧 ID 就停止。最多 13 次主页读取（首屏 + 12 次滚动），连续 3 次未发现新 ID 或发现达到 500 条时结束本轮有界扫描。完整 ID 预筛选最多取最近 2000 条本地记录。默认主页检查预算：刷新前 8 条、回溯前 30 条；可用既有采集设置调整到 1–50 条，自动任务与手动任务采用相同规则。导航间隔 9–13 秒，页面读取 20 秒、搜索私有请求 60 秒、其他私有请求 45 秒，扫描缓存／整轮扫描 10 分钟上限。

每次私有请求只返回一条详情或一个主页进度，Core 立即保存，再请求下一步。任务保留主页读取、发现、跳过与详情访问次数。正文和作者归属验证通过的记录标记 acquisition_complete；发布时间模糊时保留原始标签和未知精度。未成功记录不进入跳过集合。日期标签按 UTC+8 保留日期，不把日期移到 UTC 前一天；补充详情不降低已保存日期精度。

扫描位置只包含版本、作者稳定身份、模式、预算与后端不透明游标。重启／重试从主页重新扫描，通过本地 ID 去重；登录／验证、取消、超时和页面上下文变化均明确停止，已提交笔记保留。超时会销毁失去响应的页面，再次操作重建；取消清理该任务的缓存。

## 2026-10-07 BUG-042：已收录笔记占检查名额
