## 1. BUG-119：收件箱选中卡片边缘被遮挡（真 Bug，不是观感问题）

### 现象

收件箱里选中的卡片，只有**右边和下边**有信号青描边与取景框角标；
**上边和左边被抹掉**，看上去像卡片被裁了一角。

### 根因

`.inbox__grid` 同时是网格和滚动容器（`class="inbox__grid scroll-y"`），
而 `.scroll-y` 是 `overflow-y: auto; overflow-x: hidden`——**裁切发生在容器的 padding 边**。
M31 把选中态改成「外发光环 + 取景框角标」，两者都画在卡片边界之外：

- 外发光环：`.content-card.is-selected` 的 `box-shadow` 0 0 0 5px；
- 取景框角标：`fx.css` 的 `::after { inset: -6px }`（M35 按方案改成 -8px）。

而 `.inbox__grid` 当时**没有任何内边距**，卡片紧贴网格的内容边。
于是溢出部分落在裁切线之外：

| 方向 | 外扩落点 | 结果 |
| --- | --- | --- |
| 右 | 落在与下一列的 12px 间隙里 | 可见 |
| 下 | 落在与下一行的 12px 间隙里 | 可见 |
| 上 | 越过网格顶边 | **被裁** |
| 左 | 越过网格左边 | **被裁** |

也就是说：不是"卡片自己少画了边"，而是**滚动容器把它自己的边裁掉了**。

### 修复

按方案「轻科幻层」一节的做法（`[data-fx="on"] .grid { padding: 8px 8px 16px; margin: -6px -8px 0; }`），
但产品结构多了一层裁切：`.view__body` 也有 `overflow: hidden`，网格的负外边距伸出去的部分
会被它再裁一次。因此两条规则要一起改：

```css
/* views.css */
.view__body.inbox { overflow: visible; }   /* 让网格的负外边距伸进 .view 的内边距 */
.inbox__grid {
  padding: 10px 10px 16px;   /* 给外发光环 + 角标留出余量 */
  margin: -10px -10px 0;     /* 等量负外边距把卡片位置拉回与页头对齐 */
}
```

`.view` 的左右内边距是 24px，网格外扩 10px 仍在纸面内，不会碰到详情面板。

验收脚本 `m33-zhiliu-renderer.cjs` 用几何量断言这件事：选中卡片的四条边与网格裁切线的距离
必须 ≥ 角标外扩量（8 + 1.5 = 9.5px），不是靠肉眼判断。

## 1.5 方法：把参考页的 CSS 整体移植过来，再机器对拍

M31/M32 是「按感觉改样式」，结果只做到七成像。本期换成可核对的做法：

1. **参考页样式探针**（`/tmp/ref-probe.cjs`）：在 Electron 里打开参考页，
   逐页显示、逐个选择器取计算样式，导出 JSON。
2. **移植器**（`scripts/m35-build-zhiliu-css.cjs` + `scripts/zhiliu-map.cjs`）：
   把参考页的 CSS **整条**搬进产品（`electron/renderer/styles/zhiliu.css`），
   只做一件事——把演示类名换成产品真实类名。规则顺序与取值一律不动。
   轻科幻层同样从参考页移植，生成 `fx.css`。
3. **清冲突器**（`scripts/m35-strip-conflicts.cjs`）：产品自己那套旧规则还在，
   会「漏」出参考页没有的属性（参考页没写圆角、产品写了 → 多一圈圆角）。
   这一步按参考页每个选择器**实际声明了哪些属性**，
   把产品同名规则里参考页没声明的视觉属性删掉，删完重新继承，与参考页一致。
4. **产品样式探针 + 对拍**（`scripts/m35-style-probe.cjs` / `scripts/m35-style-parity.cjs`）：
   在正式 Renderer 里逐页取同样的计算样式，与参考页导出结果逐属性比，
   差多少报多少，报告落在 `docs/verification/phase51/m35/parity-report.txt`。

对拍基线：**13334 个属性，1032 处差异**（收件箱 108，其余五页 147~195）。
对拍脚本同时是回归工具——改任何一个组件后重跑，差异数不该变大。

### 2.1 优先级：等级字与自定义名分开

方案样张里卡片只显示 `sig + 高`，而方案自己又提示
「优先级沿用你自定义的名称（开箱即用的项目_教程 / 中优先级 / 娱乐_咨询），用来检查长名称的截断」。
两者只能同时成立于一个规则：**等级固定、名字可改**。

本期采用：

- 卡片：信号条 + **等级字**（高 / 中 / 低），完整自定义名放 `title`，悬停可见；
- 详情优先级分段：四段（跟随来源 / 高 / 中 / 低），等级字进段，**自定义名放分节提示行**（长名靠省略号截断）；
- 侧栏、看板列名、统计卡、筛选选项、图例：继续显示完整自定义名。

`SF.catalog.PRIORITIES[*].short` 是新增字段，表示等级本身，不随改名变化。
