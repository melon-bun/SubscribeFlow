# 智能优先级、设置整合与页面间距开发计划

日期：2026-10-24（Asia/Tokyo）
状态：**仅开发计划，尚未实施。此前本轮产生的未提交实现与测试改动已撤回。**
范围依据：本次用户要求；历史无标签内容直接使用兜底，不补标签、不提取隐藏主题、不引入向量数据库。
视觉依据：项目上级目录 `zhiliu-visual-style.html`。

## 1. 本期确定的行为

最终优先级按下列顺序解析：

1. 用户为单条内容手动指定的高／中／低。
2. 智能判断的高／中／低结果。
3. 来源默认优先级。
4. 来源也未设置时，保持未设置。

Jev 与 LLM 对业务层统一返回四个选项：`high`、`medium`、`low`、`unknown`（无法判断）。无法判断、功能关闭、连接不可用或调用失败，都进入来源兜底，不默认塞进「中」。

「无标签就兜底」适用于没有手动指定优先级的内容。有手动指定值时始终保留人工决定；这条无标签内容只是不能用于标签偏好统计。

第一版只使用现有标签及其关联关系。**历史没有标签，就没有可统计的标签分布；允许统计为空，不为凑齐分布额外处理历史。**

## 2. 隐藏的优先级偏好统计

### 2.1 统计口径

- 学习信号是用户明确设置的单条优先级。
- 每个优先级维护与之关联的标签、关联内容数，以及每个标签下最近两篇采集内容的标题。
- 包含已归档、已读、稍后处理及未处理内容，处理状态不影响统计。
- 来源默认值和模型自动结果不计入人工偏好，避免把兜底或模型自己的输出当成用户反馈。
- 标签关联可来自人工添加或已有自动打标；人工偏好的依据仍是用户设置的优先级。这个功能自身不创建标签。
- 没有标签的人工优先级记录仍正常保留在原内容上，但不计入本模块的标签分布或样本。
- 用户把优先级恢复为「自动判断」后，该条内容退出人工偏好统计。
- 同一内容关联多个标签时，每个标签各计一次；同一内容经多个来源收录，只按内容 ID 计一次。

### 2.2 数据组织

统计的唯一键为 **优先级 × 标签 ID**。同一个标签在高、中、低三档可以分别出现，各自保存自己的统计与两个标题；不把三档的样本混在一起。

| 字段 | 含义 |
| --- | --- |
| priority | 固定的 high / medium / low，显示名称可另行修改 |
| tag_id | 复用已有稳定标签 ID，不用可改名的标签名称作键 |
| content_count | 用户设为该优先级、且关联该标签的去重内容数 |
| recent_contents | 最近最多两条内容的 ID、首次采集时间和标题 |
| revision | 统计版本，用于失效判断与缓存更新 |

标签名称从现有标签目录读取。标题可以作为可重建缓存保留，内容 ID 用于去重、删除修正和追踪，不复制正文、笔记或完整采集载荷。

示例：

```text
高
  数据库：12 篇
    2026-10-24 采集｜如何分析慢查询
    2026-10-22 采集｜索引设计的常见误区
  日语：7 篇
    2026-10-23 采集｜授受表达的使用场景
    2026-10-20 采集｜敬语练习
中
  数据库：5 篇
    ……最多两个标题
低
  数据库：3 篇
    ……最多两个标题
```

“最近”按首次采集／收录时间排序，不按文章发布时间、最后修改时间或用户设置优先级的时间。时间相同时用稳定内容 ID 排序。只有一篇就存一篇，没有就不建空样本。

如同一内容同时关联多个标签，其标题可能成为多个分组的样本，这是有限的分组引用；组装模型输入时可以去重。

### 2.3 更新与空间边界

- 首次启用或升级时，从已有人工优先级与标签关联进行本地聚合；包含已归档内容，不调用模型。
- 后续仅在人工优先级改变、内容标签增删、标签删除／停用／恢复、相关内容删除或标题更新时失效并更新相关分组。
- 归档、已读等状态切换不重建分布，也不淘汰标题样本。
- 删除、改档或移除标签后，如果最近两个标题中有样本退出，按同一排序补入下一条；不足两条如实保留。
- 标签改名沿用标签 ID；停用标签不参与当前判断，恢复后按现有关系重建。内容关联本身不因统计而修改。
- 聚合计数基于全部符合条件的内容；最近两个标题只用于语义参考，不代表统计仅覆盖两篇。
- 不保存逐次推理历史或不断追加的样本集合。最多三个优先级 × 有效标签数个分组，每组最多两个标题；数据规模随标签数增长，不随采集历史无限复制。
- 可采用合并失效、按需重建与本地缓存，不能每次列表查询、每次模型调用都全量扫描历史。
- 数据可由原始内容关系重建；统计更新失败不能破坏人工优先级、标签、采集或来源兜底。

## 3. 自动判断模块与兜底解耦

### 3.1 模块边界

| 模块 | 职责 | 不承担的职责 |
| --- | --- | --- |
| 偏好统计仓储 | 维护分组计数、两个标题与版本 | 不调模型、不改变正式标签 |
| 优先级判断服务 | 组装有界输入，通过公共 AI 网关调用 LLM／Jev，解析四选一结果 | 不写人工优先级、不修改来源默认值 |
| 优先级解析器 | 依次采用人工值、有效智能结果、来源兜底 | 不进行网络调用、不触发历史补标签 |
| 设置与界面 | 配置策略、连接、来源默认值和名称，展示实际判断来源 | 不自行推算另一套最终优先级 |

沿用现有公共 AI 网关、连接配置和凭据管理。优先级的提示词与结果解析单独维护，不复用标签识别的“低分仍强取候选”逻辑。

统计仓储对判断服务提供稳定的偏好读取接口，未来替换成向量检索时，不需要重写人工优先级、来源兜底或卡片控件。本期不加入向量数据库及相关依赖。

### 3.2 判断流程

1. 有人工优先级：直接采用，模型不得覆盖。
2. 智能判断关闭：采用来源默认值。
3. 当前内容无有效标签：返回无法判断，采用来源默认值，不调用模型。
4. 当前内容有标签，但人工历史中没有可用的相关标签分布：返回无法判断，采用来源默认值。
5. 有相关偏好：向所选模型提交当前内容的标题与标签，以及相关标签在高／中／低下的计数和每组最多两个历史标题。
6. 模型返回高／中／低：保存独立智能结果，参与最终优先级解析。
7. 模型返回无法判断、返回不合法或调用失败：使用来源默认值。

本期不发送全量历史或历史正文。优先按当前内容的标签 ID 选择相关分组；输入应设长度与数量预算，超预算时采用确定性裁剪并允许无法判断，不能静默以全量数据已覆盖的口吻做结论。

计数描述用户偏好关联，不要求输出维持历史高／中／低比例。多标签指向不同档位时允许无法判断，不能仅按最高档强行决定。

LLM 必须输出受校验的四选一结构。Jev 可以对四个候选分别评分，但分值是独立判断，不能直接当作和为 1 的分类概率；采用保守门槛与候选差距校验，分歧或低分统一转为无法判断。两者的分值不共用一种“置信度”。

### 3.3 新内容、历史和自动打标的时序

- 智能功能默认关闭，用户在优先级设置中选择连接并开启。
- 开启后的新内容按流程自动判断；刚收录但尚无标签时先显示来源兜底。
- 如果现有自动打标稍后成功添加了标签，由内容标签变更事件触发一次新的判断资格检查；失败或仍无标签时继续兜底。
- 不为启用此功能批量补全历史标签，不默认对全部历史内容发起模型调用。
- 历史已有人工优先级和标签的内容参与本地统计，无论是否归档。
- 历史内容可通过选择「自动判断」请求判断；无标签时仍直接兜底。默认段已选中也要允许用户明确重新请求，不能因已处于自动模式就使入口失效。
- 批量恢复自动判断沿用同一规则，任务去重并限制并发，避免一次操作导致大量同时请求。
- 偏好统计更新主要影响后续判断，不因此自动反复重判全部历史内容。

### 3.4 结果有效性与故障处理

- 人工设置、智能结果、来源默认值分别保存，不共用覆盖字段。
- 每条内容仅保存最新智能结果及必要版本／状态；无法判断也可缓存，避免在同样输入下反复付费调用。
- 缓存和任务去重依据包含内容／标签版本、单条人工操作版本、优先级策略版本、所选连接调用版本与相关偏好版本。
- 模型返回前再次核对上述输入；用户改过优先级、改过标签、切换连接或关闭功能后，旧结果不得生效。
- 仅修改三级显示名称不改变判断语义；不得因此重跑所有任务。
- 标签移除至无标签时，旧智能结果立即退出生效范围，恢复来源兜底。
- 关闭智能判断后立即恢复人工值／来源兜底；已有人工值不变。
- 网络失败可以有限退避重试；无法判断不是调用失败，不做无限重试。
- 任务与结果需要在重启、退出、超时、删除内容后保持一致；后台失败不阻塞采集、阅读或设置。
- 多来源内容继续沿用现有来源兜底规则：取非空来源默认值中的最高等级，不另起规则。
- 列表、看板、日历、筛选计数、提醒与托盘使用同一个最终优先级口径。

## 4. 设置与前端调整

### 4.1 所有优先级配置集中到设置

将「设置 → 优先级名称」改为「设置 → 优先级设置」，包含：

1. **智能判断**：启用开关、已有 AI 连接选择（LLM／Jev）。简短说明无标签或无法判断时跟随来源。
2. **来源默认优先级**：从渠道管理迁入，保留来源名称、平台、当前默认值以及未设置选项。
3. **优先级名称**：保留三级名称、自定义名称校验和恢复默认名称。

三个区域复用现有设置卡片、表单、下拉与信号条，沿用浅色／深色主题，不增加新的视觉体系。

所有修改先进入草稿，点击「保存设置」才共同生效；取消恢复保存前状态。保存应具备一致的事务边界，失败不能出现名称已保存但来源默认值只保存一半。离开页面沿用未保存提醒。

渠道管理移除「优先级设置」分区及切换按钮，只保留渠道管理工作。内容总览中相关入口改为打开统一优先级设置；旧的来源优先级路由应兼容跳转。

内容的手动优先级控件、筛选器、看板与提醒仍在各自业务位置，不因为集中“配置”而删除这些正常使用入口。

### 4.2 卡片／详情的优先级控件

原来的：`跟随来源 | 高 | 中 | 低`

调整为：`自动判断 | 高 | 中 | 低`

「自动判断」表示系统按规则解析，不承诺本次一定使用模型。控件上方的小字展示实际采用的来源：

| 实际情况 | 小字 |
| --- | --- |
| 用户手动指定 | 单独设置 · 当前为… |
| 智能结果生效 | 智能判断 · 当前为… |
| 使用来源默认值 | 跟随来源 · 当前为… |
| 智能无法判断且来源无默认值 | 未设置 |

小字不能只按开关显示“智能判断”。智能结果与来源默认值恰好同档时，也要正确刷新来源说明，不能因为等级未变就跳过重绘。

批量操作文案改为「恢复自动判断」，自主添加的默认优先级选项同步调整。高／中／低继续使用现有信号条和自定义显示名称。

### 4.3 四个页面的间距与视觉一致性

范围：内容总览（日历／优先级）、渠道管理、标签（列表／AI 自动识别）、笔记。

当前静态检查发现：页面容器已有统一 gap，但参考样式中筛选栏的上下 margin 又叠加了一次；标签／渠道的分区切换还可能增加独立行，从而使工作区起点不一致。此项纳入既有 BUG-121 的布局适配续修，当前只是计划，尚未标记修复。

计划处理：

- 以参考稿分页面的 16px 节奏为准，由页面容器统一控制抬头至第一块工作区的距离。
- 移除重复叠加的 margin，不通过各页面单独塞空白补偿。
- 标签的分区切换对齐参考稿页头动作区；渠道优先级迁走后不留空切换栏。
- 明确工作区包含顶部统计卡／工具栏，不要求不同页面中语义不同的主表格强行位于同一屏幕坐标。
- 生成样式必须修改样式生成源及必要映射，不能只改下次生成就被覆盖的产物。
- 保留统一标题字号、说明文字、按钮高度、纸面背景、圆角、信号条及浅深主题。
- 常见与紧凑窗口均检查换行、内容滚动与设置底部保存按钮可达性。

## 5. 实施顺序与验收

本轮只记录以下开发顺序，不开始实施。

| 步骤 | 交付 | 核心验收 |
| --- | --- | --- |
| 1. 数据契约与统计 | 可重建的优先级／标签聚合和两个标题缓存 | 包含归档；无标签排除；去重；改档、删除和样本补位正确 |
| 2. 独立判断服务 | LLM／Jev 四选一契约、后台任务与有界结果缓存 | 无标签不调用；unknown 兜底；人工不覆盖；在途失效；失败重试有界 |
| 3. 最终优先级接入 | 人工 → 智能 → 来源 → 未设置 | 所有查询、统计、提醒口径一致；多来源规则不回归 |
| 4. 设置与控件迁移 | 统一设置页、自动判断分段、实际来源提示 | 保存／取消一致；旧入口跳转；同等级不同来源也更新小字 |
| 5. 视觉调整 | 四页间距、浅深主题及紧凑窗口适配 | 对照参考稿进行截图与实际几何检查，不只检查 CSS 字面值 |

必须覆盖的边界：

- 人工高优先级、有标签、已归档：进入高档对应标签计数与最新两标题选择。
- 人工高优先级、没有标签：人工值保留，不进入标签统计。
- 自动模式、没有标签：直接使用来源默认值，不补标签、不调模型。
- 当前有标签但历史分布为空，或只有来源／智能优先级：无法判断并兜底。
- 同标签跨高／中／低：各自计数和两个标题独立，模型可判断冲突为 unknown。
- 新收录内容先无标签、后由已有打标功能加标签：先兜底，再进行一次符合条件的判断。
- 删除最新样本、移除标签、改变人工优先级：计数与样本同时修正，无重复计入。
- 重复采集、多来源关联、标题更新：不制造重复样本，不改变首次采集排序。
- 原已智能判断的内容移除全部标签：旧结果失效并兜底。
- 请求期间改手动优先级后再恢复自动、换连接、改标签、关闭功能：旧结果不覆盖当前决定。
- 模型返回非法值、概率冲突、超时或断网：不强制分档、不产生无限任务记录。
- 改名、重启、功能关闭后的看板／筛选／日历／提醒均一致。
- 来源在设置草稿期间被取消订阅：保存失败或明确处理，不静默部分保存。

使用隔离数据库、假网络响应及正式 Renderer 验证流程。真实模型的偏好判断质量与离线流程正确性分别记录，不用假响应验收替代真实效果评估。

## 6. 明确不做

- 不给历史无标签内容补标签或隐藏主题。
- 不抽取无标签历史内容的标题／正文作为另一套学习样本。
- 不引入向量数据库、Embedding、全文索引或长期训练任务。
- 不生成优先级之外的新标签，不修改既有标签识别策略。
- 不要求用户历史比例成为新内容的强制分档配额。
- 不把来源默认值或模型自动结果循环纳入人工偏好。
- 不在本轮编写实现、迁移日常数据库、打包或发布。
