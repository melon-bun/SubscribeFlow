## BUG-102：采集更新触发整页闪烁

### 2026-10-24：其余页面模式切换与侧栏高亮续修（已验收）

- 用户追加复现：内容总览、渠道管理、标签切换模式，以及笔记页操作后，左侧当前导航高亮仍会闪。
- 原因：普通页面同路由参数变化仍进入全局 render；侧栏计数更新构造未带选中态的按钮，
  协调时先去掉 `is-active`，再由 syncNavState 补回，触发选中底色重新过渡。
  总览若干筛选按钮还直接调用全局 render，具有同一原因。
- 修复：普通页面内部参数变化沿用外壳；渠道／标签页签改局部协调，总览仍调用全局 render 的筛选入口
  一并改为局部更新。侧栏主导航、快捷筛选与平台项在构造时直接携带正确高亮，同步仅在状态变化时写入。
  不改变跨页草稿离开确认、地址／历史语义、分段滑块动画或业务查询口径。
- 验证：正式 Main/Renderer/Core 隔离负对照原 29 项中 25 项失败：总览／渠道／标签出现外壳断开及高亮失色帧，
  四页计数刷新和笔记迟到计数出现高亮类名重置；笔记排序／筛选面板本身原已通过。
  修复后原场景及新增四页导航首帧检查共 **33/33** 通过，模式检查的外壳断开、高亮重置、失色帧全部为 **0**。
  覆盖深浅色、来回切换、总览筛选、快速切换、历史后退、侧栏刷新及笔记迟到计数。
  Node **142/142**、滑块 **21/21**、收件箱切换 **26/26**、完整 Renderer 和 M28 笔记实机验收通过，
  包含草稿继续编辑与重启／重载持久化。采样检查改为至少取得 6 个真实帧，避免并发隐藏窗口中固定等待未产生采样。
- 状态／提交：**已修复并验证**，`34a2a3f`（main）。未禁用 CSS 动效或重做布局；
  原收件箱与后台事件链路保持。[逐帧证据与回归](verification/bug-102-view-modes/REPORT.md)。

### 2026-10-23：主动切换渠道的闪烁调查（未修复）

- 用户要求先调查原因，本轮未修改产品代码。后台采集刷新原修复仍保留，
  此次复现的是主动切换顶部平台分段、侧栏平台和来源筛选的路径。
- 复现：收件箱已有列表与详情 → 切换到另一非空平台/来源。正式 Main/Renderer/Core、
  合成临时库下，切换同步阶段旧 app/纸面节点均被移除，17 张卡片被替换为 4 张骨架，
  详情暂时消失，计数变成“—”；读取完成后显示新渠道 3 张卡片并自动恢复详情。
- 几何证据（1440×960）：主区 **782 → 1182 → 782px**，标题 top **142 → 134 → 142px**。
  纸面高度同时 **876 → 537 → 876px**。根网格存在多余空行，加载时该空行从 14px 扩为 353px；
  仅在临时窗口中把侧栏 grid-row 从 1 / 3 改为 1 后，根网格恢复一行，纸面高度恒为 890px。
  普通本地查询 17–29ms，有的切换来不及绘制中间态，有的出现 1 个骨架帧；
  对列表回执增加 600ms 隔离延迟后，特效开启/关闭均采到 **38 个骨架帧**，且同样跳变。
  采样未见整窗空白帧。上述数字属于隔离样本，不是日常数据库性能测量。
- 原因：平台/来源切换调用全局 render → renderWithScroll 清空并替换整个 app；
  inbox 的查询身份变化立即将 cache 清空 → 画骨架且无法取得所选 item；
  没有 aside 时纸面被标为 solo，套用整页宽度及另一套内边距；
  回执自动选中首条后 aside 恢复，再回到两栏。全局重建和加载期布局切换共同造成闪烁。
  此外生成样式把参考页 `.sidebar {grid-row:1 / 3}` 原样套进产品：参考页的顶栏/纸面是
  根网格的两个直接子项，产品却把二者包在同一个 shell 内，因而多生成一条空行；
  骨架内容较少时空行获得更多高度，整张纸面也随之缩短。
  每次还会重读与当前平台无关的来源目录，带来额外一次回调重绘。
- 定位：`scripts/app.js`（Renderer）399–413、292–295、673；
  `scripts/views/inbox.js` 135、160、254、277、320；`styles/layout.css` 523–530。
  纸面高度问题另定位到 `styles/zhiliu.css:144` 的侧栏跨行规则及产品 shell 嵌套。
  后台 renderView 已使用 reconcileWithScroll，但主动切换入口仍调用整页 render。

  将参考页根网格规则适配产品 shell 结构，消除隐式空行；

  来源目录可与列表查询缓存分开。**尚未实施，不能标记已修复。**

### 2026-10-20：后台采集刷新（已验收的历史范围）

- 现象／复现：用户报告小红书、知乎每采集一篇笔记整个页面闪一下。正式 Renderer 隔离复现中，纯进度和内容＋进度两种事件都会清掉20张卡片，出现骨架，主内容区被替换3次、15个骨架帧。
- 预期：进度就地更新；内容在后台读取并合入，保留当前卡片／详情、阅读锚点、滚动、选择、焦点、编辑草稿和AI补打预览。切换查询与路由后迟到结果不污染页面，任务终态和最终内容／计数可靠落定。

## BUG-119：收件箱选中卡片的上边与左边被遮挡

- 日期：2026-10-23；状态：**已修复，M35 实机几何断言通过**。发现于「静流」完全复刻（5.1 期 M35）。
- 现象：收件箱里选中的内容卡片，只有**右边和下边**有信号青描边与四个取景框角标；
  **上边和左边不见了**，看上去像卡片被裁掉一角。深浅色主题都有。
- 复现：收件箱 → 点任意一张卡片使其成为当前选中项 → 看卡片四条边。
  浅色与深色主题下均是「右、下有边，上、左无边」。
- 预期：选中态的描边、外发光环与取景框角标是卡片的一部分，四条边与四个角都应完整可见。
- 原因：**不是卡片自己少画了边，是滚动容器把它自己的边裁掉了。**
  `.inbox__grid` 同时是网格和滚动容器（`class="inbox__grid scroll-y"`），
  而 `.scroll-y` 是 `overflow-y: auto; overflow-x: hidden`——裁切发生在容器的 padding 边。
  M31 把选中态改成「外发光环（box-shadow 0 0 0 5px）+ 取景框角标（`::after { inset: -6px }`）」，
  两者都画在卡片边界之外；而当时 `.inbox__grid` 没有任何内边距，卡片紧贴网格内容边。
  溢出部分落在裁切线之外的只有两个方向：
  右（落在与下一列的 12px 间隙里）、下（落在与下一行的 12px 间隙里）→ 可见；
  上（越过网格顶边）、左（越过网格左边）→ **被裁**。
  产品结构比方案多一层裁切：`.view__body` 也有 `overflow: hidden`，
  网格的负外边距伸出去的部分会被它再裁一次，所以只改网格不够。
- 修复范围：只改收件箱网格的留白与裁切链，不动卡片、详情、业务与刷新链路。
  - `views.css`：`.view__body.inbox { overflow: visible; }`（让网格的负外边距伸进 `.view` 的内边距），
    `.inbox__grid { padding: 10px 10px 16px; margin: -10px -10px 0; }`
    （先给外发光环与角标留 10px 余量，再用等量负外边距把卡片位置拉回与页头对齐；
    `.view` 左右内边距 24px，10px 外扩仍在纸面内，不碰详情面板）。
  - `fx.css`：选中卡片按方案改成 1.5px 真边框 + 4px 光环，角标外扩改 -8px；
    边框吃掉 1.5px，内边距同步 `calc(var(--s-card) - 1.5px)`，卡片内容不位移。
- 验证：
  - 新增 `scripts/m35-zhiliu-renderer.cjs`：**用几何量断言，不靠肉眼**——
    选中卡片的四条边到网格裁切线的距离必须 ≥ 角标外扩量
    （角标 ::after 的 inset:-8px 相对**内边距框**，卡片有 1.5px 边框 ⇒ 越出边框 6.5px），
    否则判失败；实机通过。
  - 另建「样式对拍」工具链（`scripts/m35-style-probe.cjs` + `scripts/m35-style-parity.cjs`）：
    参考页与产品实机逐选择器、逐属性取计算样式并比数值，
    报告落在 `docs/verification/phase51/m35/parity-report.txt`。
    这一条 Bug 正是它先报出来的——肉眼比版式漏掉了「上边和左边被裁」，
    因为右、下两边落在网格间隙里、看上去是好的。
  - 截图证据：`verification/phase51/m35/01-inbox.png`（浅色）、`11-inbox-dark.png`（深色）。
  - 回归：Node 142/142；`renderer-smoke` 全段通过；`v049-batch01/02/03` 与 `m26`～`m29` 实机脚本通过。
