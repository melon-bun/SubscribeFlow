## 使用方式

在“渠道管理 → 同步方式”点击“手动刷新”或“每 N 小时”，打开同步设置。
每个订阅可独立切换手动 / 自动；默认手动，自动间隔默认 24 小时、最大 144 小时。
界面以小时输入，可用小数，精确到分钟；沿用原接口最小 5 分钟的限制。
切回手动保留间隔设置并停止该订阅的自动任务；“暂停订阅”同时禁止手动和自动采集。

切换到自动或修改间隔后，从保存时起计算下一次检查。成功的手动刷新同样推迟下次自动检查，避免紧接着重复采集。
自动模式下仍可手动刷新；已有同来源扫描时合并为同一个任务。已保存内容幂等更新，阅读、稍后处理和归档状态保持不变。
自动刷新每次默认一页，是近期窗口检查，不表示补齐全部历史；历史回溯仍由用户发起。

自动采集需要应用仍在运行、电脑未休眠。关闭最后一个窗口会退出应用，没有后台系统守护进程。
重开或唤醒后每个过期计划只补一次检查，不补跑关闭期间的每个时间点。
界面显示下一次检查、等待原因和任务来源（手动 / 自动 / 恢复）。

## 调度与恢复

Python `Scheduler` 负责持久化计划与状态；任务仍走 `SyncService` 和原有提交入口。
新 SQLite schema v2 保存 `schedules`、`schedule_blocks`、任务分页预算及触发来源，订阅增加 `sync_mode`。
到期优先；每次派发间隔默认 5 秒，共享资源的任务请求间隔默认 3 秒，分页间释放资源。
最多有一个自动刷新和一个恢复中的历史回溯等待资源，防止长回溯阻挡其他来源。

| 情况 | 处理 |
|---|---|
| 临时网络错误、TIMEOUT、可重试失败 | 默认最多追加 3 次，间隔 60 / 120 / 240 秒；用尽后显示原因，等待手动重试 |
| RATE_LIMITED | 按错误的来源 / 连接 / 资源作用域等待，不早于 retry_after；受同一重试上限约束 |
| 登录失效、INTERACTION_REQUIRED | 持久化阻塞，不自动反复验证；用户完成交互并检查连接成功后错峰恢复 |
| DEPENDENCY_UNAVAILABLE | 等待依赖恢复，最多每 5 分钟检查一次；手动模式不进行后台检查 |
| SCHEMA_CHANGED | 暂停该 backend 的失败操作；普通连接检查不解除，成功的手动列表采集可解除列表阻塞 |
| 来源不存在、其他不可重试错误 | 停止该来源自动计划并显示原因，其他来源继续 |
| 用户取消 / 暂停 / 改配置 | 不记为平台失败；终止旧配置任务，保留已提交数据 |
| Core 退出或电脑休眠 | 活动任务标 interrupted；自动模式的扫描恢复原模式和预算，从头安全重扫；手动模式等待用户操作 |

详情任务不产生定时计划；中断后可在任务区手动重试。既有 waiting 状态在重启时保留，不因进程重启绕过登录或平台限制。
Main 通过 `powerMonitor` 向 Core 发送私有 `system.power`，普通业务 Renderer 无此权限。
启动和唤醒默认等待 10 秒再分批调度；检测到较大的时钟跳变同样延迟派发。
Core 异常退出时，正常桌面应用最多在 5 / 15 / 45 秒后尝试恢复；稳定运行 60 秒后重置次数，持续崩溃时保留手动重启入口。

## 策略配置

用户在界面调整每个订阅的模式与间隔。开发或部署时可在已忽略的 `.runtime-paths.json` 增加 `schedulePolicy` 对象，
由 Main 传入 Core 的 `--schedule-policy`，支持以下字段；`schedule.status` 返回有效策略供检查。
这些是可调整的保守初值，未以真实账号长时间压测宣称最优频率。

| 字段 | 默认值 | 含义 |
|---|---:|---|
| tick_seconds | 1 | 本地到期检查间隔（秒，不是平台请求间隔） |
| startup_delay | 10 | 启动 / 唤醒后等待秒数 |
| dispatch_gap | 5 | 自动任务派发间隔秒数 |
| resource_gap | 3 | 同资源采集任务请求间隔秒数 |
| retry_base / retry_cap | 60 / 3600 | 重试基础 / 最大退避秒数 |
| max_retries | 3 | 每轮最多自动追加重试次数 |
| dependency_interval | 300 | 依赖检查最短间隔秒数 |
| page_budget | 1 | 每次定时刷新页数 |

## 升级与数据

v1 → v2 前使用现有一致性备份机制生成 `subscribe-flow.before-v2.backup`。
已有订阅统一保持手动；旧默认 3600 秒改为 86400 秒，超过新上限的历史设置收敛到 259200 秒，其他合法自定义值保留。
升级不删除订阅、内容和用户处理状态。重新添加取消的订阅也默认手动。
本次只在隔离目录验证升级，没有操作用户日常数据库或登录状态。
