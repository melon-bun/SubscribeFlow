# 收件箱切换渠道闪烁：原因调查

2026-10-23，起始 HEAD `7a61b95`。**仅调查，产品代码未改。**
统一状态沿 [BUG-102](../../../BUG_FIXES.md) 记录为新增主动切换范围待修复；
原有后台采集刷新修复保持原结论。

## 已确认的显示过程

在 1440×960 的正式 Electron 窗口中，合成样本由全部 17 条切换到 GitHub 的 3 条：

1. 点击筛选立即替换整个 app，旧纸面、侧栏与顶栏节点断开。
2. 列表缓存清空，17 张内容卡变成 4 张骨架，页头计数变为“—”。
3. 当前缓存里没有所选内容，详情列消失；纸面进入 solo 单列模式。
4. 新列表返回，自动选中首条并恢复详情列，纸面回到两栏。

| 测量 | 切换前 | 加载中 | 完成后 |
| --- | --- | --- | --- |
| 内容卡 / 骨架 | 17 / 0 | 0 / 4 | 3 / 0 |
| 详情列 | 有 | 无 | 有 |
| 主区宽度 | 782px | 1182px | 782px |
| 纸面高度 | 876px | 537px | 876px |
| 标题 top | 142px | 134px | 142px |
| 主区内边距 | 26px 26px 0 | 18px 24px 20px | 26px 26px 0 |

同步 DOM 替换发生在一次 JavaScript 执行中，不等于浏览器一定会绘制整窗空白。
实际逐帧采到的是骨架/内容替换和几何变化；本次采样的整窗空白帧为 0。
查询足够快时，中间态可能没有赶上绘制，所以闪烁会随时机和查询耗时变化。

## 对照

| 操作 | 本地列表读取/总回执时间 | 骨架帧 |
| --- | --- | --- |
| 顶部平台分段 | 19.1ms | 0 |
| 侧栏平台 | 17.4ms | 0 |
| 来源下拉 | 28.7ms | 1 |
| 顶部分段，关闭特效 | 20.6ms | 0 |
| 顶部分段，额外延迟 600ms | 627.7ms | 38 |
| 顶部分段，额外延迟 600ms，关闭特效 | 619.2ms | 38 |

六组操作均同步进入上表的加载态，旧 app 与纸面节点均被替换。
特效关闭仍能完整复现，说明装饰动效不是这条闪烁链路的必要条件。
每次筛选还额外读取一次全局来源目录；它不依赖当前平台，却随列表缓存一起清空。

另两组测量确认了纸面高度缩短的独立原因：生成 CSS 的
`.sidebar {grid-row:1 / 3}` 假定顶栏与纸面是根网格的两个直接子项，
而产品把顶栏与纸面包在一个 `.shell` 内。侧栏跨行强制产生了第二条空网格行。

| 高度探针 | 切换前 | 加载中 | 结果返回 |
| --- | --- | --- | --- |
| 原始根网格行高 | 946 / 14px | 607 / 353px | 946 / 14px |
| 原始纸面高度 | 876px | 537px | 876px |
| 临时限制侧栏为第 1 行：根网格行高 | 960px（单行） | 960px（单行） | 960px（单行） |
| 同一临时对照的纸面高度 | 890px | 890px | 890px |

该对照只给临时窗口注入一条样式，没有编辑源文件。它消除了纸面高度变化，
卡片/骨架替换与详情列的宽度跳变仍存在，说明几处原因需要分别处理。

这是合成库的本机测试，不表示用户日常库的查询时间。来源下拉组在目录加载完成后
重建一次控件才开始计时；初次异步目录加载后的下拉回调是否同步更新需单独确认，
本轮不以该旁支判断闪烁原因。

## 代码位置和范围

- `electron/renderer/scripts/views/inbox.js:254`、`app.js:292`：主动筛选调用全局 render。
- `app.js:399`、`core/dom.js:85`：构建新 app，清空旧树后追加。
- `views/inbox.js:135`、`:277`：查询身份变化清缓存，未加载时立即画四张骨架。
- `views/inbox.js:320`、`app.js:673`：没有 item 时不画 aside，并启用 solo。
- `styles/layout.css:523`、`:529`：solo 同时改变列宽与主区内边距。
- `styles/zhiliu.css:144`：侧栏跨两行与当前 shell 嵌套不符，根网格出现空行，放大纸面高度跳变。
- `views/inbox.js:160`：回执自动选中首条，使详情和双列恢复。
- `app.js:644`、`:661`：后台回包使用局部协调；主动切换没有使用这条保留外壳的路径。

缓存清空和全局替换是已有逻辑；本轮前一次细节提交未新增这些行为。
后续应适配根网格/侧栏结构，同时处理主动筛选的更新范围及加载期间的两栏布局稳定性，
并继续隔离过期请求。
来源目录的独立缓存可以减少额外请求，但单独减少该请求不足以消除栏宽跳变。
