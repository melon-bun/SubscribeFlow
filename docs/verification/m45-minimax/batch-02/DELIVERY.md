### 1.2 调度策略对付费请求的保护

- 付费渠道（描述符 `paid=True`）遇 `TIMEOUT`／`TRANSIENT`／`retryable`／中断时**不自动重放**：
  那一次调用扣费结果未知，重放等于再花一次钱。改为等下一次**用户明确启用**的周期检查，
  或用户手动重试——两者在实现上分开。
- 密钥无效／积分不足／服务不可用：连接被停用（block），用户处理后经**本地**连接检查恢复
  （本地检查不联网，因此恢复本身不花钱）。
- 默认手动：不开启自动检查就不会有自动消费。

### 1.4 一并修掉的实质问题

**BUG-129 数据串来源**：列表入库前两道核对——①响应 `wxid` 必须等于来源 `external_id`；
②每篇文章的 `biz` 必须等于来源的规范 biz。任一不符**整页拒绝**（`INVALID_RESULT`），一条都不入库；
已发生的 `code=0` 费用照记为已确认消费。

**BUG-130 关闭竞态**：付费任务纳入 Core 关闭——关库前取消并等待在途任务；晚到响应不写库；
退出有界；关库后不再写账本（那条「开始」记录留给下次启动按「结果未知」结算，费用可追溯）；
关闭后拒绝新的付费调用。

7. 回溯检查点按「来源 + 连接」维度保存；同一来源换连接会各自有检查点。
